Balancing Robot - Two Generations of Control System Design

Personal Project · Rowan University

Designed and built a two-wheeled balancing robot ("Carl Bot") from the ground up as a control theory learning platform - full sensor fusion and PID control stack implemented, though I moved on to a second-generation redesign before finishing the balance tuning. The V2 platform reuses that same control architecture while adding a mini PC, ROS 2, and an Intel RealSense depth camera for autonomous environmental perception. Both generations share a Teensy microcontroller, an MPU6050 IMU, a Kalman filter for sensor fusion, and a PID controller driving NEMA 17 stepper motors through DRV8825 drivers.

Motivation

Learning Control Theory by Building an Unstable System

A two-wheeled self-balancing robot is a classic inverted-pendulum problem: the system is open-loop unstable, so it only stays upright through continuous, correct feedback control. That made it an ideal personal project for getting hands-on with sensor fusion and closed-loop control, rather than just studying the theory.

The first version, Carl Bot, got the full sensing and control stack designed, wired, and running on a simple aluminum-extrusion frame. The second version reuses that same control architecture but rebuilds the platform around a mini PC and ROS 2, turning the balancing chassis into a base for autonomous navigation experiments.

Generation 1 - Carl Bot

Kalman-Filtered PID Balance Control

Carl Bot relies on a Teensy microcontroller for real-time computation. An MPU6050 IMU gathers gyroscopic and accelerometer data, giving the controller information about the robot's orientation. That raw data is noisy on its own, so it is processed through a Kalman filter to produce a clean, accurate estimate of angular velocity and tilt angle.

To stay upright, the robot drives two NEMA 17 stepper motors through DRV8825 stepper drivers, with motor power intended to be set by a PID (Proportional-Integral-Derivative) control loop computing the error between the robot's current angle and its desired upright position. The design combines Kalman-filtered sensor fusion with PID control - the standard architecture for this class of inverted-pendulum problem - though I never finished tuning the loop to a reliably self-balancing state before moving on to the V2 platform.

Control Architecture

  • Teensy microcontroller as the real-time control loop processor
  • MPU6050 IMU for gyroscope and accelerometer measurement
  • Kalman filter for sensor fusion, tilt angle, and angular velocity estimation
  • PID controller computing motor power from angle error
  • Two NEMA 17 stepper motors via DRV8825 drivers for balance correction
Generation 2 - In Development

Adding ROS 2 and Depth Perception

The second-generation robot builds on Carl Bot's proven foundation while retaining the core control stack: real-time processing via a Teensy microcontroller, orientation data from an MPU6050 sensor, and a Kalman filter for accurate sensor fusion. It continues to use a PID control loop for balance, driven by the same NEMA 17 stepper motor and DRV8825 driver combination.

This iteration introduces a modular, redesigned enclosure for easier access and modification, and integrates a mini PC running Linux with ROS 2 alongside an Intel RealSense depth camera, enabling autonomous environmental perception through point cloud mapping. A dedicated cooling system was also added to manage thermal performance during extended operation.

New in This Iteration

  • Modular, redesigned enclosure for easier access and modification
  • Mini PC running Linux with ROS 2 for onboard autonomy
  • Intel RealSense depth camera for point cloud mapping and environmental perception
  • Dedicated cooling system for sustained thermal performance

Reflection & Current Status

Where This Actually Stands

Both generations are honestly incomplete. I got the hardware built, the sensor fusion and PID architecture designed and wired, and the V2 chassis redesigned around a mini PC and ROS 2 - but I never finished tuning either robot to a reliably self-balancing state, and neither has driven under its own control. This page is a record of the design work, not a demo of a finished result.

What's actually there: a working Kalman filter reading the MPU6050 and producing clean tilt estimates, a PID loop wired to the stepper drivers with gains that were never fully tuned, and - on V2 - a mechanically complete platform with the mini PC, ROS 2, and RealSense camera installed but not yet integrated with the balance controller. Picking this back up would mean starting from a tuning session, not a rebuild.
